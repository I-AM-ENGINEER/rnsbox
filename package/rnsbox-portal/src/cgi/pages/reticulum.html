HaLow modem (SLIP)

Optional point-to-point serial link (sl0) to an external WiFi-HaLow RNode modem over a UART. When the modem is reachable, the Add to rnsd config button below routes Reticulum through it (a TCPClientInterface named after the modem's hostname). Off by default.

Link (sl0) __SLIP_LINK_STATUS__
__HALOW_LIVE_BLOCK__

Wire a hardware UART to the modem, cross TX↔RX, common ground, 3.3 V TTL — pads and device are board-specific (Pi: /dev/serial0; rnsbox CVITEK boards: UART1 = ttyS1 on XGPIOA[28]/[29]); see the board README. Baud must match the modem — the factory 2 Mbaud is generated exactly on every rnsbox board (96 MHz UART clock). The one exception is the classic LicheeRV Nano-e: its 25 MHz UART clock tops out below 2 Mbaud, use 1500000 there. The IPs must match the modem's SLIP config (defaults 192.168.7.2 modem / 192.168.7.1 box).

Bluetooth (BLE)

Short-range radio transport (typically tens of metres): the box scans for nearby Reticulum BLE peers and accepts inbound connections over its own GATT server, so phones and other nodes reach it with no setup. Runs on the onboard BT controller where the board has one (Zero 2 W via the miniuart-bt firmware overlay; Pi 3/4/5 by default) or any USB BLE dongle. With no adapter it degrades into a logged no-op — rnsd keeps running, everything else is unaffected, and a dongle plugged in later is picked up within 30 seconds. Runs over BlueZ + D-Bus; the BLE link itself is far slower than WiFi (announce pacing adapts automatically).

RNS Shell (rnsh)

A root shell reachable from anywhere on the Reticulum network. Client: pip install rnsh, rnsh -p prints your identity hash (goes into the allow-list below), then rnsh <destination> and disconnect with ~. Authentication is by that allow-list only — the service refuses to start with an empty one. Off by default.
